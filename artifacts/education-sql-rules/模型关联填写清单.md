# 模型关联填写清单

适用：原始扫描的18表逻辑名称。来源模型为左侧、目标为右侧。基数是业务预期，真实物理外键和唯一性仍需数据库核对。

MANY_TO_ONE=多对一；ONE_TO_MANY=一对多；MANY_TO_MANY=多对多。

## 三、条件关系：核对名称与唯一性后配置

| 来源模型 | 目标模型 | 关联基数 | 关联条件 |
|---|---|---|---|
| `tb_score_overview` | `tb_school` | `MANY_TO_ONE` | `tb_score_overview.xx = tb_school.s_name` |
| `tb_score_indicator` | `tb_school` | `MANY_TO_ONE` | `tb_score_indicator.school_name = tb_school.s_name` |
| `tb_score_contribution` | `tb_score_indicator` | `ONE_TO_MANY` | `tb_score_contribution.exam_batch_id = tb_score_indicator.exam_batch_id AND tb_score_contribution.track = tb_score_indicator.track AND tb_score_contribution.line_code = tb_score_indicator.line_code` |
| `tb_elite_class` | `tb_score_overview` | `ONE_TO_MANY` | `tb_elite_class.exam_batch_id = tb_score_overview.exam_batch_id AND tb_elite_class.school_id = tb_score_overview.xx AND tb_elite_class.class_name = tb_score_overview.bj AND CASE WHEN tb_score_overview.xkkm LIKE '物%' THEN '物理类' WHEN tb_score_overview.xkkm LIKE '史%' OR tb_score_overview.xkkm LIKE '历%' THEN '历史类' ELSE '' END = tb_elite_class.track` |
| `tb_fraction_bar` | `tb_score_overview` | `ONE_TO_MANY` | `tb_fraction_bar.exam_batch_id = tb_score_overview.exam_batch_id` |
| `tb_assign_band` | `tb_exam` | `MANY_TO_ONE` | `tb_assign_band.exam_batch_id = tb_exam.exam_batch_id AND tb_assign_band.subject = tb_exam.subject` |

三组条件说明：

- 总览xx=学校s_name、达线school_name=学校s_name仅适用于学校名称一致且唯一；school_id不能根据列名猜含义。
- 贡献分→达线汇总：贡献分须按批次+方向+线种唯一，且预测线版本一致。
- 尖子班→总览：要求尖子班的学校存值与xx一致、配置批次/学校/班级/方向唯一，且track明确是物理类或历史类。方向为空或代表全体时应单独设计筛选。
- 预测线→总览：fraction_bar须按批次唯一，否则会扩行。
- 赋分档→试卷：每批次同科只允许匹配一份试卷，否则不能选MANY_TO_ONE。
- 题目知识点桥接表分成两条MANY_TO_ONE；不要把question_id单独当桥接表主键。

## 四、两组关系建议先用语义视图处理

| 来源模型 | 目标模型 | 关联基数 | 关联条件 |
|---|---|---|
| `tb_score_indicator` | `tb_score_overview` | `MANY_TO_MANY` | `tb_score_indicator.exam_batch_id = tb_score_overview.exam_batch_id AND tb_score_indicator.school_id = tb_score_overview.xx AND CASE WHEN tb_score_overview.xkkm LIKE '物%' THEN '物理类' WHEN tb_score_overview.xkkm LIKE '史%' OR tb_score_overview.xkkm LIKE '历%' THEN '历史类' ELSE '' END = tb_score_indicator.track` |
| `tb_score` | `tb_score_overview` | `MANY_TO_ONE`（补充批次字段后） | `tb_score.student_id = tb_score_overview.anon_stu_id AND 成绩模型的exam_batch_id = tb_score_overview.exam_batch_id` |

**修正：达线汇总与学生总览跨全部线种关联时，应视为多对多，不能泛称一对多。** 一条达线记录对应很多学生，同一个学生也会匹配多条线种记录。直接SUM学生分或参考人数会重复。

原始tb_score没有exam_batch_id。需要先经tb_exam取得批次，在视图/新来源模型中暴露该字段；不要将上表最后一行含中文说明的条件原样粘贴。总览按匿名学生+批次应唯一，方可认为多对一。

复合关联在界面需要多个条件，条件之间使用AND。“关联基数”不决定查询必须INNER或LEFT JOIN；需要保留空维度数据时在查询/视图中明确处理。

CSV包含前三组32条候选关联，四列格式便于复制，不是现有Studio支持直接导入的MDL文件。
