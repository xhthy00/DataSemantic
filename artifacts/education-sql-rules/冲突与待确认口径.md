# 配置前需要统一的口径

这里记录源码中的差异，以及哪些地方还不能直接当成最终语义规则。详细公式和代码位置可按编号在 [完整规则](./学情SQL业务规则梳理.md) 或 [JSON目录](./业务规则目录.json) 中查找。

## 最先处理的六项

| 事项 | 原项目表现 | 语义配置需要确定什么 |
|---|---|---|
| **真实0分** | 基础统计、SQL提示与lint要求排0；导入却允许已选科学生的真实0分；教研均分也未统一排0 | 你已确认真实0保留；宽表还要结合选科排除未选科0。规则K01/K02/I01 |
| **学生范围** | 提示默认在籍；部分局端只在问“应届”时筛；达线预计算没有统一在籍条件；教研有的路径仅排市报 | 默认只统计在籍还是全体？市报和往届是否单列？规则D10/L14/J01 |
| **原始分或赋分** | 全市排名、五分段的化生政地用转换分；教研均分坚持读tb_score原始分 | 两套指标分别命名，不能配置一个泛称“化学成绩”覆盖所有分析。规则T03/T04/J01 |
| **缺小题行** | 普通诊断只计算存在的小题行；难度曲线补0；教研小题还会用整科人数补缺行 | 空白代表未答、缺数据还是缺考？是否按场景保留不同规则？规则Q01/Q07/J08/I05 |
| **满分缺失/不同** | 有的MAX满分默认100，有的用观测最高分推断，有的直接60/85判定 | 正式来源建议试卷满分；满分缺失需未分类，跨卷按各自满分判断。规则K05/C01/H08 |
| **排名含义** | RANK、DENSE_RANK和顺序编号并存；当前与上场的舍入时机也不同 | 哪种排名？同分是否并列？先舍入还是先排？明确参赛池和最小人数。规则R01/R11/R12/R14/J04 |

| K14 | SQL结果回装用四舍五入后的标准差平方算方差；Python用原始标准差平方 | 统一VAR_SAMP或统一精度路径 |

## 默认参数不是全部同一个开关

原项目基础配置默认及格60%、优秀85%、良好70%、低分40%；分段60/70/80/90%；临界±5分；退步≤−10分；原始分差偏科≥20分；薄弱知识点默认60%。

这些值来自不同入口：系统库异常配置、源码常量、schema默认、函数入参、SQL提示词。部分入口还有报告自己的硬编码。改变一个系统参数，不保证所有报告都同步。

DataSemantic 的MDL也不会自动读取原项目的 `edu_anomaly_config`。迁移时应明确参数来源、适用业务和版本；先人工核对，再决定是写入表达式/视图还是由应用传参。

## 推荐确认记录格式

```text
规则编号：K02 / K06 / K07
适用范围：学校科目成绩汇总（原始分）
确认内容：真实0分有效；空分及无成绩记录缺考；满分60%及格
学生范围：待确认：仅在籍 / 全体 / 其他
满分缺失：待确认：不判定并列未分类人数 / 指定回退方案
生效版本及日期：自行填写
验证样本：150分卷89不及格、90及格；0分入有效分母；NULL不入分母
```

优先把你要用的主题确认好即可；与该主题无关的教研特例、预警流程，可以后续再处理。
