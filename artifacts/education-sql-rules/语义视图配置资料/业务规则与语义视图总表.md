# 学情业务规则与语义视图配置总表

本资料把此前153条源码规则整理为43个候选视图主题和2张应用/治理卡。它是配置设计资料，视图可以按需要合并或拆分，不要求一次创建43个。43个视图主题现已全部附完整独立SQL；新增27份依据明确标注的默认假设生成，业务口径仍待确认。

日期：2026-11-03。适用模型：原始扫描草稿中的18个`tb_*`逻辑模型。和此前四模型练习草稿的`exam_scores`等名称不同，请选择正确草稿。

## 1. 每张配置卡包含哪些数据

| 配置资料 | 用途 |
|---|---|
| 业务规则、适用场景、示例问题 | 判断这张视图解决什么业务问题 |
| 视图名称、可粘贴业务说明、只读SQL/SQL文件 | 对应Studio添加视图的3个输入项 |
| 涉及模型、字段类型及字段说明 | 确认扫描模型提供了哪些原始数据 |
| 模型关联名称、来源、目标、基数、完整条件 | 说明业务数据如何拼起来；手写JOIN同样需要这些条件 |
| 输出粒度、输出字段、指标公式与单位 | 防止人数重复、均分和率口径混淆 |
| 过滤参数、学生范围、空值/零分及分母规则 | 明确哪些记录参与统计 |
| 旧规则与目标差异、待确认事项、验证状态 | 决定是否可以发布 |

## 2. 打开与使用顺序

1. 在下面按业务问题选择一个主题，打开[配置卡明细](./语义视图配置卡.md)，按V编号查找。
2. 在原始tb_*草稿中确认涉及模型和字段，先检查关联键唯一及数据范围。
3. Studio → 语义视图 → 添加视图：填写卡片中的视图名称、业务说明，复制对应SQL文件。
4. SQL文件只放SELECT/CTE，不放CREATE VIEW。视图不依赖其他新视图，避免级联支持差异。
5. 保存并校验，在SQL预览用SELECT查询新视图；真实结果另在授权查询工具中对账，再发布。
6. 每份新增SQL开头均附草案假设；先核对人群、阈值和分母，再作为正式业务规则发布。

目前仅及格60%、真实0分保留、空/无记录缺考是你明确确认的口径。优秀85%、良好70%、低分40%、知识点薄弱60%、各类排名门槛、临界±5等是旧默认/约定，需分别确认。

## 5. 共同边界和发布前提

- 原项目不少路径排0；附带的基础科目SQL采用你确认的真实0分保留。宽表未选科0仍要通过选科信息识别。
- 基础科目SQL保留全部已记录人群；总分/分段等按student_status分组，排名和部分教研草案显式限定在籍。各自范围见配置卡与SQL开头注释；基准和排名的人群过滤必须放在正确层级。
- 没有应考底表时，不能从不存在的成绩行算出全部缺考人数。null_score_count只统计已有记录中的NULL成绩。
- 学校均分/学校率跨校合并要汇总分子分母；班级等权均分属于另一个明确命名的指标。
- 满分缺失时，基础SQL将有分但无法判断及格的人数列为unclassified_count；不能默认它们不及格。
- 所有SQL依赖原始字段映射、主键和业务复合键唯一；LEFT JOIN保留缺失维度不等于数据质量已通过。
- 权限、匿名开关、预警通知/确认、导入校验和预计算刷新是应用流程，MDL业务说明不会自动实施它们。
- SQL预览只生成物理SQL；本次未连接真实业务库、未修改Studio、未发布版本。
- PostgreSQL与DuckDB目标均经当前Wren规划；虚构数据执行采用DuckDB目标SQL。PostgreSQL真实执行及数据对账仍待业务验收。
