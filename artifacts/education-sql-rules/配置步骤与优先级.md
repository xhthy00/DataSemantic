# 从数据库扫描到语义规则：配置步骤

你的目标是把“学校均分怎么算、哪些人参与、及格线是多少”等约定配置成以后可重复使用的查询。自动扫描完成的是认表、认字段；下面这些业务口径需要你选择并确认。

本次只整理文件，没有替你修改 Studio，也没有改源项目或连接数据库。完整清单见 [153条业务规则](./学情SQL业务规则梳理.md)，存在分歧的地方见 [冲突与待确认口径](./冲突与待确认口径.md)。

## 1. 先把规则放对位置

| 你要配置的内容 | Studio / 系统中的位置 | 例子 |
|---|---|---|
| 这张表是什么，一行代表什么 | 模型与字段 → 编辑模型 → 显示名称、业务说明 | tb_score：学生单科试卷成绩，一行是一名学生一份卷 |
| 这个字段表示什么 | 模型与字段 → 字段业务说明 | score：原始得分；exam_score：该科试卷满分 |
| 两张表怎么连接 | 模型关联；或者在语义视图 SQL 中显式 JOIN | 成绩.exam_id = 试卷.id |
| 每行可以算出的量 | 字段 → SQL 表达式 + 计算字段 | 及格线、是否有成绩、是否及格 |
| 哪些人参与，怎么分组，怎么算均值或比率 | 语义视图 → 添加视图 → 只读语义 SQL | 按考试、学校、科目汇总均分及格率 |
| 默认考试或本次学校 | 查询条件 | 使用稳定 ID，避免把“2026届高三1月期末”写死在可复用基础模型里 |
| 谁可以看哪些人、哪些列 | 查询执行服务的权限配置 | 本校、本班、本人；不能只写模型说明 |
| 阈值更改、预计算刷新、提醒确认 | 应用配置 / 数据处理流程 | 预测线变化后重算 indicator；MDL 不自动执行刷新 |

**业务说明负责解释；SQL表达式、JOIN、WHERE、GROUP BY 才决定实际怎么算。** 在说明里写“0分保留”，但 SQL 仍是 `score > 0`，实际仍会排除0分。

## 2. 第一轮只配置基础成绩，不要一次做153条

先在工作空间选中你从数据库扫描得到、包含原始表的草稿。你当前页面可能是后来建的四模型统计草稿，它的逻辑名称和原始18表草稿不同；先看“模型与字段”确认名称。

建议第一轮配置顺序：

1. 考试批次：`tb_exam_batch`；试卷：`tb_exam`；学校：`tb_school`；科目成绩：`tb_score`。
2. 给这四张表写清中文说明和“一行代表什么”。
3. 核对三条关系：`tb_score.exam_id = tb_exam.id`、`tb_exam.exam_batch_id = tb_exam_batch.id`、`tb_score.school_id = tb_school.id`。
4. 确认一次考试与单科试卷的区别，科目及格使用每份卷满分。
5. 建一个“学校科目均分及格率”语义视图，再用你熟悉的小样本核对。

显式 JOIN 的视图 SQL 可以先完成汇总；只有要用 `school.name` 等导航计算时，才需同时正确建立导航字段和关系。不要只添加关系名称而没有正确关联条件。

## 3. 先填写这张业务口径卡

| 项目 | 你当前问题的配置值 |
|---|---|
| 业务名称 | 各学校、各科目的平均分和及格率 |
| 基础数据 | tb_score 科目成绩，关联试卷、批次、学校 |
| 输出一行 | 一次考试 × 一所学校 × 一个科目 |
| 考试条件 | 查询时选“2026届高三1月期末”；模型保留批次ID供以后换考试 |
| 学校、班级归属 | 取当次成绩记录的学校/班级 |
| 成绩类型 | 科目原始成绩；赋分另起名称，不混在同一个指标里 |
| 有效成绩 | **你已确认：空成绩或无记录为缺考，真实0分保留** |
| 及格判断 | **你已确认：成绩 ≥ 该科卷面满分 × 60%** |
| 平均分 | 有效分数合计 ÷ 有效成绩人数 |
| 及格率 | 及格人数 ÷ 可判定及格的有效成绩人数 ×100 |
| 满分缺失 | 建议列“未分类人数”，不悄悄按100分或不及格处理；需要你确认 |
| 学生范围 | 在籍生 / 全体 / 指定范围：**尚需确定**，旧项目不同入口不一致 |
| 显示精度 | 平均分、百分率一般2位，先计算后显示舍入 |

“没有成绩记录的人是缺考”是一条业务定义，但**只查 tb_score 不可能数出所有没出现的人**。要统计“应考人数、缺考人数、参考率”，还需要应考名单或可靠的选科名单作为底表。仅有成绩时可以算已知有效成绩的均分和及格率，不要虚构缺考人数。

满分完整时，“可判定及格的有效成绩人数”就是有效成绩人数。满分不完整时，应同时显示两个数，避免分母悄悄变化。

## 4. 在 Studio 中逐步配置

### 第一步：为表和字段补说明

在“模型与字段”中可以使用下面的中文说明：

```text
模型说明：学生单科试卷成绩。每行是一名学生在一份单科试卷中的成绩。
用户口中的一次考试对应考试批次，一次批次可以有多份科目试卷。
统计按当次成绩的学校和班级归属；真实0分有效，空分属于缺考。
未选科必须单独识别，不能将宽表所有0分都算成实考。
```

字段说明至少补齐：学生标识、批次标识、试卷标识、科目、学校、班级、原始得分、卷面满分。逻辑名称可以先沿用扫描结果，中文意义写在显示名称/业务说明里；批量改逻辑名会影响已有 SQL 引用。

### 第二步：把基础判定写成表达式

逐行规则的意思是：

```text
有效成绩：存在成绩值；0分仍算有效。负分、超过满分先进入质量问题清单。
及格线：每份试卷满分 × 0.60。
是否及格：分数和满分都齐全且满分大于0时才判断，缺信息时返回空值。
```

若在同一模型里已有 `score` 和 `exam_score` 两列，可以将下面作为**表达式示意**，根据实际逻辑字段名调整后验证：

```sql
-- 及格线
CAST(exam_score AS DECIMAL(18, 4)) * 0.60

-- 是否及格：1=及格，0=不及格，NULL=无法判定
CASE
  WHEN score IS NULL OR exam_score IS NULL
       OR CAST(exam_score AS DECIMAL(18, 4)) <= 0 THEN NULL
  WHEN CAST(score AS DECIMAL(18, 4))
       >= CAST(exam_score AS DECIMAL(18, 4)) * 0.60 THEN 1
  ELSE 0
END
```

此处0.60来自你确认的业务要求。优秀比例85%、低分40%、薄弱知识点60%只是原项目默认值，不能因为这个例子而一起认定。若正式满分以试卷表为准，应通过正确关系取满分，或直接在视图 JOIN 后计算。

### 第三步：添加汇总语义视图

进入“语义视图 → 添加视图”：

```text
视图名称：exam_school_subject_summary

业务说明：
按考试批次、学校和科目汇总原始成绩平均分、有效成绩人数、及格人数和及格率。
及格线按每份试卷满分的60%计算；真实0分保留，空成绩不进入有效成绩分母。
满分缺失时另列无法判定人数。学生范围和缺考计数方式以已确认规则为准。

只读语义SQL：
先从成绩关联试卷、批次、学校；建立有效成绩和是否及格判定；
再按批次ID、学校ID、科目分组，输出分数和/人数/均分/及格人数/率。
```

这里需要真正的 SELECT 查询，不能把上面的中文步骤贴进“只读语义SQL”当配置。可以拿本目录对应的原项目 SQL 示例作为起点，请开发人员或 AI 按口径卡生成适配当前逻辑模型的 SQL。

旧项目有不少 PostgreSQL 特有语法，Wren也有自己的支持边界。请一次验证一个视图。若引用另一个视图报“找不到表”，将基础逻辑写进同一视图的 CTE/子查询，不预设当前版本支持所有级联视图写法。

### 第四步：保存、验证，再做 SQL 预览

1. 保存草稿，执行模型验证。
2. 在“SQL预览”中对该语义视图写 SELECT，按批次ID筛选目标考试。
3. 查看生成的物理 SQL 是否使用正确物理表、正确关联和分母。
4. 用已知的小样本在允许查询的工具中核对结果，再发布。

当前 Studio 的“生成物理SQL”是规划步骤，**不会执行数据库查询**。验证成功说明模型/查询能够被处理，不代表均分口径已被业务认可，也不代表查到了真实统计结果。

## 5. 以后按业务主题逐步增加

| 优先级 | 建议语义视图 | 先解决的规则 |
|---|---|---|
| 第一批 | 学校/班级/科目基础成绩汇总 | K01–K20、D01–D18，先统一0分、满分、学生范围 |
| 第二批 | 三门/四门/六门总分、原始分与赋分分布 | T01–T11，分开原始和赋分，不重新猜总分 |
| 第三批 | 学校和班级排名、优势薄弱 | R01–R14，明确参赛池、并列和最小人数 |
| 第四批 | 各线达线、班级达线、线带 | L01–L14，保留线种维度，分母避免重复 |
| 第五批 | 小题表现、知识点掌握 | Q01–Q08、N01–N11，确定缺题补零和权重 |
| 后续 | 教研、进退步、干预预警 | J/H/C/A 系列，先审核特例和经验阈值 |

不必每条规则建立一个视图。通常一个业务主题有一层可靠明细，加若干可复用汇总即可。参数、展示窗口、权限和流程规则分别留在合适的位置。

```text
4. 对“需确认/实现差异/冲突”逐项说明，不自行选一种当成最终标准。

6. 按当前Wren版本验证，不假设PostgreSQL SQL可以原样运行。
7. 只给配置内容和步骤，不直接修改我的Studio或数据库。
```
