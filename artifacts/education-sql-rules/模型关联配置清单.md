# 学情分析模型关联配置清单

字段顺序与Studio一致：关联名称、来源模型、目标模型、关联基数、关联条件。使用原始扫描草稿的tb_*逻辑模型名称。名称统一为`rel_来源_to_目标`，名称关联额外加`_by_name`。

共34项候选；其中21项可优先按字段定义配置，5项先核实业务，8项存在名称/粒度/第三模型等前提。下面基数表示预期业务关系，**本次未实时验证物理外键、唯一性和孤儿记录**。即使来源字段允许为空，也不必因此改为一对一。

`MANY_TO_ONE`=多对一；`ONE_TO_MANY`=一对多；`MANY_TO_MANY`=多对多。基数方向按本表来源→目标，不按图中的父子箭头猜。

## 三、存在额外前提的8项

这部分用于梳理候选关系。请先阅读表后逐项说明；R29和R33尤其不适合作为当前模型中的直接关联。

| 编号 | 关联名称 | 来源模型 | 目标模型 | 关联基数 | 关联条件 |
|---|---|---|---|---|---|
| R27 | `rel_score_overview_to_school_by_name` | `tb_score_overview` | `tb_school` | `MANY_TO_ONE` | `tb_score_overview.xx = tb_school.s_name` |
| R28 | `rel_score_indicator_to_school_by_name` | `tb_score_indicator` | `tb_school` | `MANY_TO_ONE` | `tb_score_indicator.school_name = COALESCE(tb_school.s_name, tb_school.name)` |
| R29 | `rel_score_indicator_to_score_overview` | `tb_score_indicator` | `tb_score_overview` | `MANY_TO_MANY` | `tb_score_indicator.exam_batch_id = tb_score_overview.exam_batch_id AND tb_score_indicator.school_id = tb_score_overview.xx AND tb_score_indicator.track = CASE WHEN tb_score_overview.xkkm LIKE '物%' THEN '物理类' WHEN tb_score_overview.xkkm LIKE '史%' OR tb_score_overview.xkkm LIKE '历%' THEN '历史类' ELSE NULL END` |

| R31 | `rel_elite_class_to_score_overview` | `tb_elite_class` | `tb_score_overview` | `ONE_TO_MANY` | `tb_elite_class.exam_batch_id = tb_score_overview.exam_batch_id AND tb_elite_class.school_id = tb_score_overview.xx AND tb_elite_class.class_name = tb_score_overview.bj AND (tb_elite_class.track = '' OR tb_elite_class.track = CASE WHEN tb_score_overview.xkkm LIKE '物%' THEN '物理类' WHEN tb_score_overview.xkkm LIKE '史%' OR tb_score_overview.xkkm LIKE '历%' THEN '历史类' ELSE NULL END)` |
| R32 | `rel_fraction_bar_to_score_overview` | `tb_fraction_bar` | `tb_score_overview` | `ONE_TO_MANY` | `tb_fraction_bar.exam_batch_id = tb_score_overview.exam_batch_id` |
| R33 | `rel_score_to_score_overview` | `tb_score` | `tb_score_overview` | `MANY_TO_ONE` | **当前不可直接填写，见说明** |
| R34 | `rel_assign_band_to_exam` | `tb_assign_band` | `tb_exam` | `MANY_TO_ONE` | `tb_assign_band.exam_batch_id = tb_exam.exam_batch_id AND tb_assign_band.subject = tb_exam.subject` |

**R27｜条件关系：先处理前提再配置**

最新导入保存原始XX文字；应核对编码前缀、校区名、空白和名称唯一性。禁止直接xx=tb_school.id。

**R28｜条件关系：先处理前提再配置**

代码实际ON ind.school_name=COALESCE(sch.s_name,sch.name)。indicator.school_id可能同样存学校名，不能直接与sch.id等同。

**R29｜不建议建立：跨线种事实对事实**

补齐批次、学校、方向仍为多对多：一个学校方向有多条线种汇总及多名学生。不能把它当ONE_TO_MANY后直接聚合成绩，建议在专用视图中计算。

**R30｜条件关系：先处理前提再配置**

两侧先过滤相同批次，确认线种唯一及阈值版本；NULL批次旧数据不能直接丢弃或擅自跨场匹配。

**R31｜条件关系：先处理前提再配置**

如配置指定track，还需和xkkm归一方向匹配；school_id在此按xx语义存值，需确认是名称。 本清单按空track代表不限定方向处理，需确认与实际业务一致。

**R32｜条件关系：先处理前提再配置**

保证分数线配置每批次唯一，再按学生方向选wl或ls列；不能把各方向所有线阈值混用。

**R33｜不能直接用当前两模型条件表达完整关系**

只写tb_score.student_id=tb_score_overview.anon_stu_id会跨考试串行。完整路径是先tb_score.exam_id=tb_exam.id，再同时匹配overview.anon_stu_id=score.student_id和overview.exam_batch_id=exam.exam_batch_id。建议在refSql/语义视图中JOIN，或先为成绩业务模型暴露批次ID；未完成前不创建此关系。

**R34｜条件关系：先处理前提再配置**

并非字段声明外键；同批次同科有多卷时不唯一。更常用来解释overview等级，见下文。

## 四、界面填写示例

以成绩关联试卷为例：

```text
关联名称：rel_score_to_exam
来源模型：tb_score
目标模型：tb_exam
关联基数：MANY_TO_ONE（多对一）
关联条件：tb_score.exam_id = tb_exam.id
```

复合关联R08需两行条件并用AND连接：exam_id=exam_id，student_id=student_id。复杂CASE/COALESCE条件需要高级条件编辑；不要为了可视化选字段而删掉额外条件。

保存关系后，若需要通过导航计算字段取值，再添加导航字段，例如在tb_score中添加名称paper、类型tb_exam、关联rel_score_to_exam。通过关系导航访问字段与手写语义视图JOIN是两种使用方式。
